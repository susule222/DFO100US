# US100 v2.24 名单行布局恢复（2026-09-18）

## 结论先行

- **脱壳验证**：frida 转储了运行时映射的 DFO.exe（194,392,064 字节）。逐节比对磁盘文件：
  `.rdata/.data/.pdata/.rsrc/.tls/.themida` 全部字节一致；`.text` 仅 1 字节不同
  （RVA 0x38B7350，0x40→0x48，正是 ngs_stub 的窗口守卫补丁，见 ngs_stub.c:498）；
  `.idata` 是加载器正常的 IAT 重写。**Themida 在运行时并不改动代码段**，磁盘反汇编即
  真实执行代码，静态分析是精确的，无需脱壳。

- **v2.24 名单行布局已恢复并接入**（`-roster-v224` 开关）：
  行 = u16 槽位 + u32 名称长度 + 名称字节 + 93 个定长标量字节（6×u8、
  3×u32、4×u8、2×u32、u8、u32、u8、u32、25×u8 标志、u32、u16、3×u8、
  u32、2×u16 疲劳、u32、尾部 u8）。头部（mode 2、两个上下文字节、3×u16、
  1×u32、1×u16 计数）和 4 字段尾与 v2.38 一致。

- **行布局已逐字节钉死（2026-09-18 复核）**：行 = u16 槽位 + u32 名称长度 + 名称，
  之后 89 字节定长（合计 95 定长 + 名称）。名称之后的读点（行内偏移）：
  `u8 x6@12`、`u32@18`、`u32@22`、`u8@26`、`u32@27`、`u8 x4@31`、`u32@35`、
  `u32@39`、`u8@43`、`u32@44`、`u8@48`、`u8@49`、`u32@50`、`u8 x26@54`、
  `u32@80`、`u16@84`、`u8 x3@86`、`u32@89`、`u16@93` + `u16@95`（疲劳对）、`u32@97`。
  此前的版本总长一样，但把偏移 49 的那个 u8 放到了行尾，49 之后所有字段整体错位
  1 字节：客户端读到偏移 89 的 u32 时跨过了疲劳字节 156(0x9C)，把 `0x9C000000`
  渲染成 `-1,677,721,600`；疲劳对也提前两字节，显示恒为 `0+0`。修正后疲劳行显示
  `156+0`（日上限 156），天文数字消失。回归测试见 `TestCharacterListV224FatigueOffsets`。

- **职业/进阶字段位置已由单次二分实测确定**：六个字节中
  **第 2 字节低 4 位 = 职业**（0-15，正好覆盖全部基础职业），**第 4-6 位 = 进阶**；
  第 1、3 字节置 0，**第 4 字节 = 等级**。判定依据（`-roster-layout-probe`，
  四个候选行的值都是 3=法师，行标签随行发送所以视觉顺序无关）：
  - 第 2 字节低 4 位 = 3 的行 → 法师头像 + "Mage" 职业文字 ✓
  - 第 1 字节 = 3 的行 → 仍是 Slayer（该字节无可见作用）
  - 第 2 字节第 4-6 位 = 3 的行 → 头像与职业文字全空（职业 0 + 进阶 3 的组合非法）
  早先"法师显示 berserker"就是因为把打包值放进了第 3 字节：第 2 字节保持 0（Slayer
  职业）→ 剑士头像，第 3 字节 3 → berserker 职业文字。

- **字节级验证**：frida 挂钩客户端读字符串路径，捕获到的字节为
  `75 73 31 30 30 61` = "us100a"，与服务器发送完全一致。行解析器被调用
  6 次（两次角色 × 3 次刷新），无错位、无崩溃，全程 300 秒稳定。
  新布局下客户端还新发了命令 217（旧布局从未出现），说明名单被正确消费。

- 职业/转职压缩字节的 nibble 语义已通过反汇编 + 视觉反馈确证（2026-09-18）：
  行解析器（0x3807616..0x380763e）把第 3 个 u8 拆成 `(b>>4)&7` 与 `b&0xf` 两个
  独立字段。初版按「低 4 位职业、bit4-6 转职」打包，法师行发 f3=3，客户端渲染成
  **剑士头像 + berserker 文本**（职业 0 + 转职 3 的 Slayer 狂战士）。因此正确语义
  是 **bit4-6 = 职业、低 4 位 = 转职**，编码为 `(profession&7)<<4 | advancement&0xf`。
  第 4 个 u8 是等级（用户已确认等级显示正确）。另两个 u8 保持 0。职业字段只有 3 位，
  扩展职业（knight=12 等）的线上编码待后续专项恢复。
